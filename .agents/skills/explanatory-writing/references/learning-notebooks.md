# Learning notebooks

Use the notebook to connect an explanation with an observable result. Keep each experiment focused on an idea the reader is ready to understand.

- Before a code cell, explain its purpose and what the reader should inspect, compare, or change. Keep setup instructions brief and separate from the conceptual lesson.
- Interpret the result beside the experiment. Name the meaningful pattern in a chart or output and explain its relationship to the question being studied.
- For controls, explain what the parameter changes and what a useful comparison would reveal. For static figures, tell the reader which axes, traces, or regions matter.
- Keep toy examples small enough to inspect. Identify simplifications and the limits of the conclusions they support.
- Build later experiments on earlier observations. Extend the mechanism toward practical consequences, trade-offs, or failure cases as the subject warrants.

These are teaching preferences. They do not require widgets, a particular library, or changes to working code during a prose-only edit.
