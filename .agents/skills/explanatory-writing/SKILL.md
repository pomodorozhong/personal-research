# Explanatory writing

Help a curious reader understand a subject, follow its mechanism, and choose what to explore next. Use patient explanations and concrete examples, with enough detail to follow the reasoning.

All resources are bundled in this skill folder. Copy the whole folder to reuse it; no project documents, external examples, other skills, services, or scripts are required.

## Workflow

1. Establish the document's purpose, audience, and requested scope. Preserve the user's supplied views, existing technical meaning, and required formats. A writing task does not require changing working code or adding experiments.
2. Read [writing-principles.md](references/writing-principles.md) for tone, pacing, terminology, formatting, authorial voice, evidence, and qualifications. Then read only the relevant format guidance:
   - **Topic index:** [topic-readmes.md](references/topic-readmes.md) for named guide links and the questions they answer.
   - **Guide, research explanation, or source walkthrough:** [guides-and-walkthroughs.md](references/guides-and-walkthroughs.md) for learning progression, worked examples, analysis, and code tracing. Use this for a README that contains a complete lesson.
   - **Supporting document or case collection:** [case-collections.md](references/case-collections.md) for galleries, annotated examples, and reference collections that readers skim or compare alongside a main guide.
   - **Learning notebook:** [learning-notebooks.md](references/learning-notebooks.md) for explanations around experiments and interpretation of outputs. Also read the walkthrough guidance if it teaches an existing implementation.
   - **Visual explanation:** [visual-explanations.md](references/visual-explanations.md) when adding, placing, or revising figures alongside prose in any of these formats.
3. Draft or revise around the reader's question. Introduce each concept before using it, connect examples with interpretation, and put relevant evidence and limitations beside the claims they support. Choose the shape by purpose, rather than filename; combine references only when the task combines forms.
4. Use [editorial-review.md](references/editorial-review.md) for the final pass or a requested review. Resolve substantive issues before cosmetic consistency. For a review presented as a table, use [review-table-template.md](assets/review-table-template.md) and fill it with actual passages, precise links, and targeted revisions. Follow the user's requested presentation when it differs.

## Delivery

For edits, describe the concrete changes and checks actually performed. For reviews, make each critique traceable to the writing and distinguish rules already covered from rules that need strengthening or addition. Do not claim that instructions alone guarantee future writing quality.
